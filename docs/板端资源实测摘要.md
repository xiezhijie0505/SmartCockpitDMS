# SmartCockpitDMS 多进程方案 — 板端资源实测摘要

> 平台：RK356X　架构：`dms_capture` + `dms_ai` + `SmartCockpitDMS`（POSIX shm + 疲劳 IPC）  
> 场景：三进程全开、监控运行、有人脸（代表正常驾驶监测负载）  
> 说明：本组为**多进程现状验收**，不含单进程对照；单进程补测后可在文末表中追加一列。

---

## 1. 测试项与方法

| 项目 | 方法 | 说明 |
|------|------|------|
| 内存 / 泄漏 | `rss_sample.sh` 采三进程 VmRSS | 观察是否随时间爬升 |
| CPU 分布与总量 | `cpu_sample.sh` 采三进程 `%CPU` | 单核=100%，多核进程可 >100% |
| 预览帧率 | HMI 画面显示 FPS | 目视稳定区间 |

`%CPU` 含义：相对**单个 CPU 核**的占用；合计超过 100% 表示使用了多个核。

---

## 2. CPU 占用

### 2.1 分进程

| 指标 | dms_capture | SmartCockpitDMS (HMI) | dms_ai |
|------|-------------|------------------------|--------|
| 平均 (%) | 11.7 | 271.3 | 28.1 |
| 最小 (%) | 0.0* | 0.0* | 0.0* |
| 最大 (%) | 14.0 | 297.5 | 31.5 |

\* 最小为 0 来自采样首点（尚无时间差），填表时以**平均 / 最大**为主，可忽略首点 0。

### 2.2 总量（多进程合计）

\[
\text{CPU 合计} \approx 11.7 + 271.3 + 28.1 = \mathbf{311.1\%}
\]

约合 **3.1 个核**（若 SoC 为 4 核，本业务栈约占整机算力的大部分峰值能力中的约 3 核当量）。

### 2.3 简要结论

- 负载可按进程拆开观察：采集轻、AI 中等、**HMI 最重**。  
- 推理已独立在 `dms_ai`（约 28%），与界面进程分离。  
- HMI 平均约 271%，说明预览 / 人脸识别 / Qt 刷新仍是主要 CPU 消耗；后续优化应优先看 HMI，而非再压采集。  
- 本组**不能**直接得出「比单进程更省 CPU」；若需对比总量，须用同等场景再测单进程一列的 `%CPU`，与 **311%** 对比。

## 3. 内存（VmRSS）与泄漏

### 3.1 典型量级（采样片段）

| 进程 | 典型 RSS | 约合 MB | 变化特征 |
|------|----------|---------|----------|
| dms_capture | 12736 kB | ≈ 12.4 MB | 全程不变 |
| SmartCockpitDMS | 266752～267264 kB | ≈ 260.5～261.0 MB | 极小台阶后平台期 |
| dms_ai | 31188～33824 kB | ≈ 30.5～33.0 MB | 小幅震荡，无单调爬升 |

### 3.2 泄漏判读

- capture：完全平台期。  
- HMI：约 +0.5 MB 量级后持平，**不视为泄漏**。  
- AI：在约 31～33 MB 间波动，**不视为泄漏**。  

**结论：本段采样内三进程均表现为平台期，无明显内存泄漏迹象。**  
（若报告需要「长时间」表述，建议另附 ≥30～60 分钟 RSS 长测；短测结论写「短期无明显泄漏」。）

### 3.3 内存总量（粗算）

\[
12.4 + 261 + 32 \approx \mathbf{305\ \text{MB}}
\]

（未单独计入 POSIX shm 映射在各进程中的重复统计细节；量级以 RSS 表为准即可。）

## 4. 预览帧率（FPS）

| 项目 | 结果 |
|------|------|
| 预览 FPS | **19～23** |
| 场景 | 多进程全开、有人脸、监控运行中 |

**结论：** 预览帧率稳定在约 20 FPS 量级，满足座舱预览可观看需求；未出现持续掉到个位数的卡顿区间（以本次目视记录为准）。

---

## 5. 综合结论（可直接用于报告）

1. **可行性：** 多进程 + shm 链路在板端可稳定运行；RSS 平台期 + FPS 约 20，具备验收意义。  
2. **CPU 结构：** 合计约 **311%（≈3.1 核）**；其中 HMI 占主导，AI / 采集相对可控，体现「推理与 UI 分进程」的可观测性。  
3. **内存：** 总量约 **300 MB 量级**，以 HMI 为主；本段采样**无明显泄漏**。  
4. **体验：** 预览 **19～23 FPS**，流畅度可接受。  
5. **与单进程对比：** 本文仅有多进程数据。补测单进程后，建议增加：

| 方案 | CPU 合计 | RSS 合计 | 预览 FPS |
|------|----------|-----------|----------|
| 多进程（本文） | ≈ 311% | ≈ 305 MB | 19～23 |
| 单进程（待测） |  |  |  |

预期表述（待数据验证）：多进程可能略增内存与调度开销，换取进程隔离与负载可归因；是否更省 CPU **以实测合计为准**，不作先验承诺。
