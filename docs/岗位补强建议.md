## 2. 岗位 A（存储 / 系统软件）——建议补什么

目标：让加分项「内核 / 文件系统 / 分布式 / 网络存储 / 数据库」里 **至少有 1～2 个能讲 15 分钟**。

### 2.1 必补（选做其一当主作品，2～4 周量级）

| 选项 | 做什么 | 面试能讲什么 | 工作量 |
|------|--------|--------------|--------|
| **A1 推荐** | 用户态小 KV / 简易数据库：Hash + 落盘 + 崩溃恢复（WAL 或 append log） | 文件 IO、持久化、索引、fsync | 中 |
| **A2** | FUSE 小文件系统（只读镜像或简单读写目录） | VFS 概念、用户态 FS、open/read 路径 | 中高 |
| **A3** | 多线程 TCP 文件/对象传输小服务（类迷你网盘） | TCP、并发、粘包、超时 | 中 |

**不推荐：** 一上来改 Linux 内核大补丁（周期长、难演示）。

### 2.2 加分（有时间再做）

- [ ] 读完并笔记：操作系统「虚拟内存 / 文件系统 / 锁」三章，能手画  
- [ ] 一个极简内核模块：`hello` + `proc` 读计数（证明摸过内核构建）  
- [ ] 用 `strace`/`perf` 分析自己 KV 的一次写路径（体现底层好奇心）  
- [ ] 分布式入门：Raft 或「多副本日志」的玩具实现 / 跟读 etcd 一篇，能说清一致性直觉  

### 2.3 与 DMS 的关系

- **不要**把 DMS 改成存储项目。  
- DMS 仅作「Linux 系统编程能力」旁证；**主打作品换成 A1/A2/A3**。

### 2.4 岗位 A 简历一句话模板

> 独立实现基于文件追加日志的轻量 KV 存储，支持崩溃后按 WAL 恢复；熟悉 Linux 文件 IO 与多线程网络服务。另具备嵌入式 Linux 多进程与 IPC 实践（座舱 DMS）。

## 3. 岗位 B（宽口径：图像 / Linux / AI）——建议补什么

目标：把现有 DMS **讲圆 + 验收做完**，再按意向部门微调。

### 3.1 优先补齐（就在本仓库，1～2 周）

| 项 | 内容 | 对应 JD |
|----|------|---------|
| B1 | **板端联调验收**：capture + dms_ai + HMI，D-Bus level 上屏 | Linux 应用 + 图像 |
| B2 | **S6 systemd**：三进程 unit，`Restart=on-failure`，能演示杀进程拉起 | Linux 系统与应用 |
| B3 | 面试稿：V4L2 流程、shm seqlock、D-Bus 为何传 level 不传图 | 问题分析能力 |
| B4 | 准备 1 个 **AI Agent 协作案例**（需求→生成→你改错→如何验证） | AI coding 优先 |

### 3.2 按投递部门选做

| 若更偏… | 补什么 | 是否新开仓库 |
|---------|--------|--------------|
| 安防 / IPC / 音视频 | 单路 **V4L2 → 画框 → RTSP → VLC** 小 demo | **建议独立小项目** |
| 座舱 / 车载 | 收尾 S6 + 简历话术（Camera/AI/HMI 解耦） | 否 |
| 纯应用 / 业务 | Qt 交互与稳定性、日志、配置；数据库若 JD 强调可点一点现有 SQL | 否 |

### 3.3 岗位 B 不必做的

- [ ] 为宽口径岗去啃内核 / 分布式（投入产出低）  
- [ ] 把 RTSP 硬塞进监控页业务（独立 demo 即可）  

### 3.4 岗位 B 简历一句话模板

> 基于 RK3568 的驾驶员监控系统：V4L2 采集经共享内存送至推理进程，疲劳等级经 D-Bus 通知 HMI；熟悉板端 Linux 多进程、图像链路与 RKNN 部署。开发中使用 AI Agent 加速实现，关键路径自行设计与验收。
